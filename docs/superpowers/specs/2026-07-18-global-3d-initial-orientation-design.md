# 全局六形体 3D 初始朝向调整设计

## 背景与问题

全局六形体 3D 背景已经完成并通过自动化验证，但实际浏览器验收发现：页面刚加载时，部分对象接近正对相机，帽面占据主要视觉面积，侧面和厚度不够明显。等待动画运行一段时间后，对象转到斜向姿态，才呈现出预期的 3D 深度。

根因位于初始姿态配置与运动相位的叠加：

- 两个 `spin` 对象直接从当前较浅的 `rotationDegrees` 开始连续旋转。
- 四个 `pace` 对象在 `t = 0` 时还会把各自 `phase` 对应的倾斜量叠加到 `rotationDegrees`。其中蓝色圆片和中性圆片的 Y 轴基础倾角几乎被抵消，因此首帧尤其接近平面。

## 目标

六个全局 3D 对象在首帧就使用稳定、错开的斜向姿态，同时露出帽面和侧面，使用户无需等待动画也能识别其立体厚度。

减弱动态模式使用同一组清晰的基础姿态。对象在正常动画开始后继续沿现有运动轨迹演化，不增加入场动画或额外过渡。

## 范围

本次只调整：

- `src/components/background/shape-3d/config/global-background3d.config.ts` 中六个全局对象的 `rotationDegrees`。
- 对应配置与姿态测试。

明确不调整：

- `src/components/background/shape-3d/triangle/` 下箭头的任何源码、测试、姿态、运动或材质。
- 六个对象的位置、几何、厚度、颜色、透明度、材质或层级。
- `spin` 的周期与转向。
- `pace` 的相位、周期、位移范围或倾斜范围。
- 相机、灯光、renderer、响应式性能档位、SVG fallback 或资源清理。

## 采用方案

直接调整每个描述符已有的 `rotationDegrees`，不增加全局起始时间偏移、运动预热或新的运行时状态。

这让基础姿态继续保持为配置的单一事实来源：

- `calculateGlobalBackgroundPose(..., 0, ...)` 从明确的对象级基础朝向开始。
- `prefers-reduced-motion: reduce` 继续直接使用同一基础朝向。
- 运动速度、相位和暂停恢复逻辑不需要改动。

不采用给动画时钟增加偏移的方案，因为它会把首帧视觉隐藏在时间计算中，并让正常模式与减弱动态模式使用不同的姿态来源。不采用增加挤出厚度或提高侧面不透明度的方案，因为问题来自观察方向，而不是几何或材质不足。

## 初始姿态

六个对象使用不同方向的 X/Y 倾斜，避免整组背景像同方向排列的展示模型；Z 轴只保留轻微偏转，不改变它们原有的视口构图角色。

| 对象 | 新 `rotationDegrees` | 正常模式 `t = 0` 的实际朝向 |
| --- | --- | --- |
| `blue-puck` | `[20, -24, -4]` | `[20, -18, -4]` |
| `neutral-puck` | `[-20, 24, 4]` | `[-20, 18, 4]` |
| `green-slab` | `[22, -26, 6]` | `[22, -26, 6]` |
| `yellow-arch` | `[-20, 24, -5]` | `[-20, 24, -5]` |
| `neutral-pill` | `[18, -22, -5]` | `[23, -22, -2]` |
| `green-cube` | `[-18, 22, 4]` | `[-24, 22, 2]` |

表格第三列包含 `pace` 对象在现有相位下的首帧倾斜叠加。所有对象在正常首帧的 X/Y 轴都至少保留约 `18°` 的可见倾角；减弱动态模式使用第二列基础朝向，X/Y 轴同样不会接近平面。

现有小对象倾斜范围最大约为 `±6°`。叠加后仍保持为围绕斜向基础姿态的小幅摆动，不会形成完整旋转，也不会越过正对相机的平面姿态。

## 组件与数据流

组件边界保持不变：

```text
GLOBAL_SHAPE_DESCRIPTORS.rotationDegrees
  → createGlobalBackgroundObject() 设置创建时姿态
  → calculateGlobalBackgroundPose() 生成首帧、动画帧或减弱动态姿态
  → global runtime 应用到对应 Group
```

`GlobalBackground3D.vue`、`App.vue` 和箭头组件不需要修改。此次调整不增加新的 props、emits、响应式状态或运行时分支。

## 测试设计

遵循 TDD，先增加会在当前配置下失败的姿态契约，再修改配置：

1. 配置测试固定六个对象的新 `rotationDegrees`，防止后续无意恢复到近乎平面的初始值。
2. 姿态测试计算每个对象在桌面宽度、`t = 0` 的实际正常姿态，验证 X/Y 轴的绝对角度均不小于 `18°`。
3. 姿态测试计算每个对象的减弱动态姿态，验证 X/Y 轴同样保持至少 `18°` 的基础倾角，并继续保持时间无关。
4. 继续运行现有运动边界、周期闭合、响应式和资源释放测试。
5. 继续运行三角箭头 SHA-256 契约测试，证明箭头文件字节级不变。

## 浏览器验收

在 `1440×900` 与 `390×844` 下检查浅色、深色和减弱动态状态：

- 页面第一帧即可从每个可见对象读出帽面和侧面。
- 右侧绿色大板达到参考截图中“等待一段时间后”的立体可读性，但不会抢过 Hero。
- 六个对象的朝向彼此错开，不形成整齐同步的模型陈列感。
- 大型对象仍保持边缘裁切，小型对象仍保持安静的视觉权重。
- 动画速度、位移边界和响应式行为与调整前一致。
- 箭头的外观与运动完全不变。
